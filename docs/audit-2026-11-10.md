## A. 损坏：会闪退、丢字或丢数据

### A1. 搜索可能闪退（已核实）
- 位置：`PhotoDiary/Intelligence/SearchIntent.swift:29-30`
- 代码：`else if let a = Self.day(from) { range = a...context.today }`
- 问题：模型只给出起始日期且晚于今天（如搜“明年的计划”，或模型给错年份）时，`ClosedRange` 下界大于上界，直接 trap。上面两端都有的分支做了 `a <= b ? a...b : b...a`，这个分支没有。
- 方向：下界晚于今天时交换或丢弃这个范围。在 `IntelligenceTests` 里补“from 在未来”的用例。

### A2. 深链接关掉正在写的编辑器，未保存的字丢失（已核实）
- 位置：`PhotoDiary/App/Router.swift:126-162`
- 问题：`.today / .onThisDay / .entry / .search` 分支都无条件 `editor = nil`；`.writeLatest` 在 600ms 后换成另一张照片的编辑器；`latestPhoto == nil` 时关掉编辑器后什么也不打开。程序关闭不经过 `interactiveDismissDisabled(isDirty)`，也不问“放弃这次修改？”。
- 触发：编辑器里写了字，切出去点小组件、锁屏小组件或跑 Siri 快捷指令（`AppIntents.swift` → `PhotoDiaryApp.swift:127`）。
- 对照：通知路径 `PhotoDiaryApp.swift:163-164` 特意写了“正在写的编辑器不顶掉，免得丢字”。
- 注意：`PhotoDiaryTests/DeepLinkTests.swift:110-114` 断言了当前（错误的）行为，要一起改。
- 方向：编辑器有未保存内容时，深链接先暂存，等编辑器关掉再执行，或走同一个“放弃修改？”确认。

### A3. 表上给已删除的照片口述，文字被静默丢弃（已核实）
- 位置：`PhotoDiary/Library/LibraryScanner.swift:155-169`，`PhotoDiary/App/WatchBridge.swift:199-204`
- 问题：`write` 里 `fetchAssets(withLocalIdentifiers:)` 取不到照片时，`performChanges` 的闭包什么都不改也算成功，`store.save` 不抛错；`drainQueue` 随后把这段移出队列并回 `.wrote`，表上显示已写入。
- 触发：在系统“照片”里删了一张最近的照片，没开 App，表上旧快照还列着它；有限访问下照片被移出可见范围同理。
- 方向：写入前确认每个 id 都取到了照片，取不到就抛错；手表端要有“这段没写进去”的状态，文字不能丢。

### A4. 手表写入队列会被一条失败的永久堵死（已核实逻辑，触发较可能）
- 位置：`PhotoDiary/App/WatchBridge.swift:205-208`
- 代码：`catch { …; break }`
- 问题：没有跳过或丢弃策略，每次 `resume()` 都从同一条开始再失败。
- 触发：`buildSnapshot`（`:128-131`）的“还没写”来自 `AssetImages.recentAssets`，包含 `.typeCloudShared`；共享相簿照片改不了说明，对它口述后队头永远失败。
- 方向：失败的那条跳过继续处理后面的，并区分“可重试”和“永远写不进”；快照里不要列出改不了说明的照片。和 A18 的 `canPerform(.properties)` 一起看。

### A5. 正在写入时到达的段落滞留到下次回前台（已核实）
- 位置：`PhotoDiary/App/WatchBridge.swift:192-211`
- 问题：`for write in pendingWrites` 遍历的是数组副本；`await store.save` 期间新 `enqueue` 调 `drainQueue` 被 `draining` 挡回；循环结束后不再检查队列。
- 触发：表离线时攒了 2 条以上，手机打开后连续送达。
- 方向：循环改成“队列非空就继续取队头”，或结束后再检查一次。

### A6. 索引库损坏后“删掉重建”实际删不掉（路径行为已核实，后果较可能）
- 位置：`PhotoDiary/Library/IndexDatabase.swift:187-191`
- 代码：`try? FileManager.default.removeItem(at: URL(filePath: url.path() + suffix))`
- 问题：`url.path()` 默认返回百分号编码，`…/Application%20Support/Index/entries.store` 再经 `URL(filePath:)` 后 `%20` 成了字面目录名，`try?` 静默失败。之后第二次 `container()` 照样失败，退回内存库，每次启动都全库重读、地名重查。
- 为什么测试没发现：`IndexDatabaseTests` 的 `corruptedEntriesStoreIsRebuiltAndPlacesSurvive` 用的临时目录没有空格；测试自己第 61 行也是同样写法。
- 方向：用 `url.path(percentEncoded: false)`，或 `url.deletingLastPathComponent().appending(path: url.lastPathComponent + suffix)`。测试改用带空格的目录。

### A7. 写入基于索引里的旧说明，可能覆盖别处的修改（逻辑已核实，触发窗口较可能）
- 位置：`PhotoDiary/Library/DiaryStore.swift:402, 424, 441-444`；`PhotoDiary/Views/Editor/EditorView.swift:355`
- 问题：`save` 和 `addTag` 取 `entries[id]?.caption ?? currentCaption(for:)`，索引优先；`renameTags` 直接用 `entry.caption`；编辑器用索引说明初始化后整条覆盖。
- 触发：App 关闭期间在 Mac 上改了说明，iPhone 被手表口述唤起；`drainQueue` 只检查 `canRead`，增量同步还没回来就用旧说明拼接后整条写回。
- 方向：写入前从照片库现读说明（`currentCaption`）作为基准，索引只用于显示。这和“说明是唯一正本”的设计一致。

### A8. 时区只在首次访问时取一次（较可能）
- 位置：`Shared/Model/DayStamp.swift:75-80`
- 代码：`private static let base: Calendar = { … c.timeZone = .current … }()`
- 问题：进程存活期间跨时区（旅行时 App 留在后台）后，`DayStamp.today`、`DiaryStore.today` 仍按旧时区算。写进说明的 `— YYYY.MM.DD` 可能差一天，而且永久写在照片里。那年今日、本周统计、`DateFormatter.localized` 的缓存同受影响。
- 方向：用 `.autoupdatingCurrent`，或监听 `NSSystemTimeZoneDidChange` 后重建并刷新派生数据。

### A9. 地名没在一次运行里查完，下次启动全部清空重查（较可能）
- 位置：`PhotoDiary/Library/DiaryStore.swift:659-662, 722`
- 问题：`placeLanguageKey` 只在 `resolvePlaces` 整轮跑完后才写入。首次全量坐标多（600ms 一个），中途进程被结束；下次启动 key 仍是 nil，不等于当前语言而 `placeCache` 非空，被当成“语言变了”，清空全部地名从头查。大库加短会话可能永远查不完。切换语言后中途被杀同理。
- 方向：开始查之前就写入语言 key（或首次没有 key 时不当作语言变化）。

### A10. 撤销照片权限后，旧日记留在小组件和手表上（已核实）
- 位置：`PhotoDiary/App/WidgetBridge.swift:38-40`；`PhotoDiary/Library/DiaryStore.swift:176`；`PhotoDiary/App/WatchBridge.swift:100`
- 问题：`update()` 先 `guard store.hasLoaded`，而 `start()` 在 `guard canRead else { return }` 之后才置 `hasLoaded`。撤销权限必然冷启动，`hasLoaded` 一直是 false，共享容器里的快照和缩略图原样留着。注释“没有照片权限时不留旧的日记在小组件上”不成立。手表 `sync()` 的 `guard store.canRead` 同理。
- 方向：无权限时也要写一份空快照并清缩略图；手表发一份空快照。

### A11. 月份分组可能出现重复 id（逻辑已核实，触发条件较少）
- 位置：`PhotoDiary/Library/DiaryStore.swift:502, 522-528`；`PhotoDiary/Views/Journal/JournalContents.swift:36`
- 问题：排序按 `sortDate`（时刻），分组键按 `entry.day`（拍摄地时区的日历日），并假设同月连续（`months.last?.id == key`）。例：无定位照片在设备时区 10/31 23:45（UTC+8），东京照片 11/1 00:30 JST 时刻更早，序列变成 …11月、10月、11月、10月…，出现两个 `"2026-10"` 的 `MonthGroup`，`ForEach(id:)` 拿到重复 id。
- 方向：按 `(day, sortDate)` 排序，或分组时用字典归并而不是只看上一组。
- 相关：同一处排序没有并列时的次序（`YearInReview.swift:43` 用 id 兜底了），同一秒的照片可能换位。

### A12. 本周回顾给模型的正文丢了首句（已核实）
